# Finish test: the strings, 2026-11-17

This family was run twice. The first run was steered by its prompt; the second was not, and this record rests on the second.

## The run this record rests on

A fresh agent was given `CODECS.md` and a list of case inputs with opaque ids, in a directory holding nothing else, and barred from the reference implementation, the fixtures, any library implementing the format, and the rest of this repository. It was also barred from the runtime's UTF-8 encoder and decoder - `Buffer.from(s, 'utf8')`, `toString('utf8')`, `TextEncoder`, `TextDecoder` - and wrote the byte level itself, because those already implement the substitution this family turns on. Its prompt named nothing about the family and pointed at no rule.

The sandbox was not sealed as tightly as that implies: the agent ran with this repository as its working directory and with the operator's instruction and memory files in its system context, one of which names this project and states what the `unrepresentable` marker covers. Its tool log shows it read neither the repository nor anything else outside its own directory, but "nothing else" describes what it was handed rather than what it could reach.

### Result

Twenty-two of twenty-two answers identical to the committed fixtures, including `ed a0 80` as three replacements, `f4 90 80 80` as four, and an unpaired surrogate announcing a count of three.

Eight of those answers are transcription rather than derivation, and the run named them: `utf8-ascii`, `utf8-trailing-bytes` and `utf8-short-input` are printed in the example slice at para. 11; `utf8-subpart-completable` and `utf8-subpart-uncompletable` are worked out in full inside `utf8-maximal-subpart`; and `utf8-empty`, `utf8-no-count` and both halves of the unpaired surrogate are each stated plainly in a rule. Fourteen were derived.

Twelve observations came back and seven are carried forward.

### What it could not settle from the document

- Which byte sequences are well formed. The document delegates that to RFC 3629 and restates none of it, and the ranges a lead byte allows behind it decide four cases. A port without the standard to hand cannot build from the document alone.
- How many replacements each example in `utf8-invalid-forms` becomes. The rule ends on a plural covering its three sequences collectively. The run derived two, three and four from `utf8-maximal-subpart`, and notes that the three examples the document picks do not discriminate: byte-by-byte replacement gives the same counts, and only the two cases the document answers outright separate the readings.
- What `utf8-maximal-subpart` does with a byte that can begin nothing. The longest completable prefix of a stranded continuation byte is empty, which taken literally is a run of length zero and a decoder that never advances. One replacement per such byte is forced by an example rather than by the rule text.
- Whether `utf8-replaces-unpaired-surrogate` carries the right marker. It is `delegated`, but its own text - an implementation whose strings cannot hold an unpaired surrogate refuses instead - is the description the document gives of `unrepresentable`. A rule carries at most one marker, and which one it carries decides whether a port with such strings may answer `unrepresentable` for two cases or is held to replacing. The run read the paragraph three times.
- Whether a decoder scanning for a maximal subpart may read past the count the string announced. The run bounded the scan at the count; peeking past it answers differently on input such as `02 e1 80 61`, and no case exercises the difference.
- What an encoder does at the top of the range. `utf8-invalid-forms` tells a decoder that an encoding above U+10FFFF is invalid and no rule says what an encoder does there. The run assumed symmetry.
- Whether a `utf8` count carries a ceiling of its own. `buffer-rejects-short-input` and `record-rejects-short-input` each say theirs does not; the Strings section says nothing.

### Noted and not carried forward

The run reported that surrogate pairing is greedy and left to right, which the document cites rather than states; that an overlong `uint` count is legal on a string under `uint-overlong-decode` and no case tests it; that two rules cover each of the two rejection cases and agree; that an astral character in a `decodes` answer is written as a surrogate pair of escapes rather than through the `units` form, since that form exists for units that do not pair; and that it inferred `read` includes the count by doing arithmetic on an example whose bytes are not shown. It also found `read` for `utf8` defined two sections away, and the little-endian spelling of a two-byte count at the top of the document.

## The first run, and why it was redone

An earlier run the same day also answered 22 of 22. Its prompt named all three questions the family turns on - how many replacements a run becomes and where a run ends, what an encoder does with text its string type can hold, and what the count counts after substitution - in the vocabulary of the rule that decides them. An audit found that four cases sit on a fork the run itself declared live, decided by `utf8-maximal-subpart`, a rule those cases do not cite. The re-run above removes the steer and the leading case ids, and reaches the same answers by the same route, so the steer was redundant rather than load-bearing.

## Method

Copy `CODECS.md` and the `input` fields of the cases to an empty directory, with the ids replaced by opaque ones, give an agent those two files and the constraints named above, and say nothing about the family. Note that eight of the 22 answers are quoted in the document; a run matching those proves transcription, not derivation.
