# Finish test: the booleans, 2026-11-17

A fresh agent was given `CODECS.md` and a list of case inputs, in a directory holding nothing else. It was barred from reading the reference implementation, the fixtures, any library implementing the format, and the rest of this repository. It implemented `bool` in plain JavaScript from the document, answered all four cases of the bool directory, and reported where the document left it guessing.

## Result

Four of four answers identical to the committed fixtures, including `02` decoding to false rather than to true or a rejection, and no bytes at all rejecting rather than reading as false.

`bool` carries three rules and four cases, so the diff settles little on its own. What the run is worth here is the reading: the document is implementable, and every gap below is a silence rather than a wrong rule.

## What it could not settle from the document

Each of these became an entry in `TODO.md` rather than an edit to either side.

- What an encoder does with a value that is not a boolean. The integer codecs have an escape hatch - a value that is not a number is outside what the rules define - and it is scoped to that section. `bool` has nothing, so a dynamically typed port chooses between truthiness and a refusal, and the two disagree on `bool` encoding 2. No case separates them.
- Whether a `delegated` rule binds the committed answer as hard as an unmarked one. The acceptance rule loosens only for `unrepresentable`, so a port that reads every non-zero byte as true makes the choice the marker predicts and is still a divergence. The run read `bool-other-byte` twice before answering false.
- Whether the hex in a case or an answer is lowercase. Every example is, and nothing says so. A port formatting through an uppercase primitive agrees on every one-byte answer and disagrees beyond that.
- That the byte is compared as an unsigned value. `ordered-record-sorts-by-the-key-bytes` says "byte by byte as unsigned numbers"; the bool rules say only that a decoder reads `01` as true. The hazard the two rules carry between them is also unjoined: a port that writes its native boolean's raw byte satisfies `bool-single-byte` on a width and violates it on a value, and the byte it writes comes back as false.
- That `bool-single-byte` is not the whole decoder rule. Read alone it invites the reading that `00` and `01` are the only defined inputs; `02` is settled two bullets later, inside the rule whose marker most invites doubt.

## Noted and not carried forward

The run also reported that the answer shape is defined far from where it is used and mixes four unrelated things in one paragraph, and that what a rejection _is_ - a throw, a sentinel, a cursor left where it was - is never stated. Both are meta-layer gaps the combinators run already carried forward. It noted in passing that a rejection's `read` count, a language with no boolean type, `bool` as an inner codec, trailing bytes after a bool, and the absence of a fixed-width or big-endian sibling are all unstated; each is inferable from rules that are stated, and none is carried forward.

## Method

The run is reproducible: copy `CODECS.md` and the `input` fields of the cases to an empty directory, and give an agent with no other context those two files.
