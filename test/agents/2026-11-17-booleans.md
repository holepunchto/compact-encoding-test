# Finish test: the booleans, 2026-11-17

A fresh agent was given `CODECS.md` and a list of case inputs, in a directory holding nothing else. It was barred from reading the reference implementation, the fixtures, any library implementing the format, and the rest of this repository. It implemented `bool` in plain JavaScript from the document, answered all four cases of the bool directory, and reported where the document left it guessing. No runtime primitive was barred, and none was needed: a byte is a byte.

The run was not sealed as tightly as that sentence implies: the agent ran with this repository as its working directory and with the operator's instruction and memory files in its system context, one of which names this project and states what the `unrepresentable` marker covers. Its tool log shows it read neither the repository nor anything else outside its own directory, but "nothing else" describes what it was handed rather than what it could reach.

The prompt steered the run, and the steer is part of what it found. It said the family is small and "the valuable half of this exercise is step 4, not the answers", and asked it to be concrete about "what a port written in a language whose boolean or byte handling differs from JavaScript's would have to decide alone". The report below leans in that direction because it was pushed there.

## Result

Four of four answers identical to the committed fixtures, including `02` decoding to false rather than to true or a rejection, and no bytes at all rejecting rather than reading as false.

All four answers are printed in the bool rules themselves, so the diff is transcription rather than derivation and settles nothing about whether the family is implementable. Twelve observations came back and five are carried forward below.

`bool` carries three rules and four cases, so the diff settles little on its own. What the run is worth here is the reading: the document is implementable, and every gap below is a silence rather than a wrong rule.

## What it could not settle from the document

Each of these became an entry in `TODO.md` rather than an edit to either side.

- What an encoder does with a value that is not a boolean. The integer codecs have an escape hatch - a value that is not a number is outside what the rules define - and it is scoped to that section. `bool` has nothing, so a dynamically typed port chooses between truthiness and a refusal, and the two disagree on `bool` encoding 2. No case separates them. The run called this its single largest gap for a port in JavaScript, Python, Ruby or Lua, and said the document's preference for refusal over coercion arguably favours the reading it did not take: it implemented truthiness and thinks it may have taken the wrong branch.
- Whether a `delegated` rule binds the committed answer as hard as an unmarked one. The acceptance rule loosens only for `unrepresentable`, so a port that reads every non-zero byte as true makes the choice the marker predicts and is still a divergence. The run read `bool-other-byte` twice before answering false.
- Whether the hex in a case or an answer is lowercase. Every example is, and nothing says so. A port formatting through an uppercase primitive agrees on every one-byte answer and disagrees beyond that.
- That the byte is compared as an unsigned value. `ordered-record-sorts-by-the-key-bytes` says "byte by byte as unsigned numbers"; the bool rules say only that a decoder reads `01` as true. The hazard the two rules carry between them is also unjoined: a port that writes its native boolean's raw byte satisfies `bool-single-byte` on a width and violates it on a value, and the byte it writes comes back as false.
- That `bool-single-byte` is not the whole decoder rule. Read alone it invites the reading that `00` and `01` are the only defined inputs; `02` is settled two bullets later, inside the rule whose marker most invites doubt.

## Noted and not carried forward

The run also reported that the answer shape is defined far from where it is used and mixes four unrelated things in one paragraph, which is a meta-layer gap the combinators run already carried forward. It also reported that what a rejection _is_ - a throw, a sentinel, an error value - is never stated, and that half is carried there too. The rest of that observation is not: nothing says whether a rejecting decoder leaves the read cursor where it found it, which a caller partway through a buffer needs in order to retry or reposition. That is an implementation contract rather than a corpus shape, and no earlier run carried it. It noted in passing that a rejection's `read` count, a language with no boolean type, `bool` as an inner codec, trailing bytes after a bool, and the absence of a fixed-width or big-endian sibling are all unstated; each is inferable from rules that are stated, and none is carried forward.

## Method

The run is reproducible: copy `CODECS.md` and the `input` fields of the cases to an empty directory, and give an agent those two files, the constraints named above and the steer quoted above. Reproducing it without the steer is a different experiment and should be expected to report differently.
